# 任務導航

1. 執行 `npm run mission`，把進度表原樣給同學看。
2. 找出第一個未完成（□）的必要任務，用一兩句話說明：這個任務是什麼、為什麼要做、大約要花多久。
3. 用選擇題問同學：「現在開始這個任務」／「我想先做別的（請說明）」／「先解釋一下這是什麼」。
4. 依任務引導：

| 任務 | 引導方式 |
|---|---|
| 準備環境 | 執行 `npm install`，說明 node_modules 是什麼 |
| 連上 GitHub | 請同學自己在終端機執行 `gh auth login`（需要他本人操作瀏覽器），完成後回來說一聲 |
| 領取地塊、建立城市 | 執行 `/new-city` 的流程 |
| 城市識別 | 選擇題：規模、色票；開放題：城市名稱、善意一句話 |
| 寫下善意企劃 | **一次只問一題**，依序問對象、問題、行動、改變、步驟。用同學的話整理成 proposal.json，字數超過就和他一起刪減 |
| 設計意圖 | 把訪談內容整理進城市的 `CLAUDE.md`，請同學確認 |
| 送出第一個 PR | `/submit` 的流程。先讓城市出現在星球上，有成就感再往下做 |
| 親手蓋城市 | 先問：尺度（一棟房子？一條街？一座都市？）、氣氛、時間（白天、黃昏、深夜）、會動的東西。再參考 `City.example.ts` 實作，先做最簡單的版本讓他看，再一起加細節 |
| 穿梭機路線 | 問同學「參觀者降落後，你想讓他依序看到什麼？」，每一站寫成一組 camera／target。用 `npm run dev` 實際飛一次，再依同學的感覺微調座標 |
| 子 UI | 先給 3 個版面方向（文字描述＋適合的理由）讓同學選，選定後才實作；可以用 `useShuttle()` 讓內容跟著站點改變 |
| 加分：review | `gh pr list` 找同學的 PR，引導同學先稱讚一個具體優點，再提出一個具體建議，用 `gh pr review --comment` 送出 |
| 加分：框架提案 | `/propose` 的流程 |

5. 完成一個任務後，再執行一次 `npm run mission`，恭喜同學並預告下一個任務。
6. 同學想跳著做也可以，任務順序是建議，不是強制。
