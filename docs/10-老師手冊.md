# 10　老師手冊

## 一、開課前設定（約 30 分鐘，只做一次）

### 1. 建立 repo 並上傳
```bash
cd project-sccd-plant              # 解壓縮後的資料夾
git init -b main
git add .
git commit -m "探索者計畫：初始框架"
gh repo create project-sccd-plant --public --source=. --push
```
> 用 GitHub Pages 免費方案需要 public repo。想要 private，需要 GitHub Pro／Team，或改用 Vercel 部署。

### 2. 修改主星設定
| 檔案 | 改什麼 |
|---|---|
| `src/site.config.ts` | `repoUrl` 改成你的 repo 網址；課程名稱、標題 |
| `.github/CODEOWNERS` | `@kaochieh224` 改成你的帳號（如不同） |
| `cities/demo-*` | 四個示範地塊（一棟房子／村落／城鎮／大都市），**開課前刪除**（保留 `kaochieh224` 作為示範） |

### 3. 開啟 GitHub Pages
repo 的 **Settings → Pages → Build and deployment → Source** 選 **GitHub Actions**。
push 一次到 main，約 2 分鐘後網址會出現在 **Actions → 部署總站**。

### 4. 保護 main 分支
**Settings → Branches → Add branch ruleset**（或 Branch protection rule），對 `main` 開啟：
- ✅ Require a pull request before merging
- ✅ Require approvals：1
- ✅ Require review from Code Owners
- ✅ Require status checks to pass：選 `check`（地塊檢查）
- ✅ Block force pushes

### 5. 建立標籤
```bash
gh label create core --color d4101a --description "老師核准的框架修改"
gh label create framework --color 171717 --description "框架提案"
```
> 學生設為 **Write** 權限，就能 push 分支、開 PR。Write 權限**也能加標籤**，所以 CI 會再確認 `core` 標籤是由 **maintain 或 admin** 權限的人加上，學生自己加的不算。
> 老師自己的帳號是 repo 擁有者（admin）；助教若要能核准框架提案，請設為 **Maintain**。

### 誰可以核准（擇一）
| 做法 | 設定 | 適合 |
|---|---|---|
| 老師審全部（預設） | `CODEOWNERS` 的 `*` 指向老師 | 人數少、想確保品質 |
| 老師＋助教 | `CODEOWNERS` 改成 `/cities/ @老師 @助教` | 30 人以上 |
| 同學互審地塊 PR | 刪掉 CODEOWNERS 裡對 `/cities/` 的限制，保留 Require approvals 1 | 想練習 code review；框架提案仍由 CI 的 `core` 檢查把關 |

### 6. 邀請學生
```bash
gh api -X PUT repos/<你的帳號>/project-sccd-plant/collaborators/<學生帳號> -f permission=push
```
或到 **Settings → Collaborators → Add people**。人數多時，可以建 GitHub Organization 並用 Team 管理。

## 二、計畫里程碑（115-1）

這個總站是探索者 studio 的作品總站，進度跟著 Notion 的探索者計畫走，這裡不另訂課程節奏。下面只列計畫裡寫明的日期；班展進場、撤場與大總評日期以年級行事曆與班級決議為準，改期時以 Notion 計畫為準，並同步 `scripts/mission.mjs` 裡的 `MILESTONES`。

| 日期 | 里程碑 |
|---|---|
| 11/6 | 計畫書確認（含暫定選賽核可、組隊方案） |
| 11/20 | W5 規格確認、鎖定主攻 |
| 12/4 | W7 可玩評圖 |
| 12/18 | W9 外部測試回報 |
| 12/25 | W10 展示頁定案、送印 |
| 12/31 | W11 班展進場 |
| 1/5 | W12 評圖暨送件預審 |
| 1/12、1/26 | 審稿日 |

**每週的要求、評分與送件規定**：請看 Notion 的探索者計畫，這裡不重複。

**這個 repo 在計畫裡的角色**：作品本體在學生自己的公開 repo 與展示頁，這裡只放總站入口。學生的任務進度（`npm run mission`）有 11 項，第 11 項是 W4 起把展示頁與 repo 網址填進作品卡。建議第一次上課先讓每個人看到自己的光點出現在線上的星圖上，成就感決定了之後的投入程度。

## 三、Review 檢查表

### 地塊 PR
- [ ] CI 三道檢查都通過
- [ ] 作品卡是學生自己的想法（尤其非傳統三問，不是 AI 編的空話）；展示頁與 repo 網址（W4 起）可以打開
- [ ] 從主星降落、每一站穿梭機都飛得到、手機版不爆版
- [ ] 地塊沒有把整張星圖拖慢（網格數量合理、沒有超大貼圖）
- [ ] 圖片有壓縮、有 alt

### 框架提案 PR（加 `core` 標籤前）
- [ ] 有對應的 Issue，且討論已有共識
- [ ] **沒有修改 `.github/workflows/`**，或修改內容你逐行看過（workflow 可以執行任意指令）
- [ ] 沒有新增來路不明的套件（看 `package.json` 與 `package-lock.json` 的變更）
- [ ] 本機 checkout 這個分支跑 `npm run build`，並抽看幾個地塊
- [ ] 公版欄位改動向下相容

## 四、防護機制一覽

| 層 | 機制 | 擋什麼 | 可被繞過嗎 |
|---|---|---|---|
| Claude Code | `.claude/hooks/guard.mjs` | Claude 編輯地塊以外的檔案 | 可以（`SOLAR_CORE=1`），這是教學用的提醒 |
| Claude Code | `CLAUDE.md` | 告訴 Claude 規則與流程 | 可以，屬於軟性約束 |
| CI | `check-scope.mjs` | 越界修改、一次改多個地塊 | 不行，除非老師加 `core` 標籤 |
| CI | `build-registry.mjs` | 公版欄位錯誤、引用禁用套件、檔案過大 | 不行 |
| CI | `next build` | 任何會讓整站壞掉的錯誤 | 不行 |
| GitHub | Branch protection＋CODEOWNERS | 未經審核合併、直接 push main | 不行 |
| 執行時 | `Universe.tsx` 的 try/catch | 某人的 `City.ts` 出錯拖垮整張星圖 | — |

## 五、老師自己修改框架
```bash
SOLAR_CORE=1 claude                  # Mac
```
```powershell
$env:SOLAR_CORE="1"; claude          # Windows PowerShell
```
修改後照常開 PR、加上 `core` 標籤。建議老師也走 PR 流程，當作學生的示範。

## 六、常見狀況
| 狀況 | 處理 |
|---|---|
| 學生改錯別人的資料夾 | CI 會擋下；請學生用 Claude Code 還原：「把 cities/xxx 還原成 main 的版本」 |
| 兩個 PR 同時改 `package-lock.json` | 只會發生在框架提案；先合併一個，另一個請作者 `git pull origin main` 後重新 `npm install` |
| 某個地塊讓網站變很慢 | 開 Issue 標記該同學；常見原因是 City.ts 網格太多（請改用 mergeGeometries 或 InstancedMesh）或圖片太大 |
| 地塊位置變了 | 地塊依帳號雜湊分配，遇到衝突時順延；新同學加入偶爾會讓少數地塊換位置（模擬：6 塊加到 36 塊，約 2 塊換位）。scenes 是以地塊中心為原點的座標，換位不受影響 |
| 學生沒有 Claude 付費方案 | Claude Code 需要 Pro 以上方案或 Console 帳號，開課前先確認 |
| Windows 上 hook 沒有作用 | hook 指令依賴 `$CLAUDE_PROJECT_DIR`；請在一台 Windows 電腦實測（未查證）：在學生的地塊模式下請 Claude 改 `src/app/page.tsx`，應該會被擋下。沒被擋也不會出事，CI 仍會把關 |
| 學生的 Page.tsx 壞掉 | 只有那一塊會顯示錯誤訊息，星圖與導覽照常運作；City.ts 壞掉則自動改用預設模型 |
