# 10　老師手冊

## 一、開課前設定（約 30 分鐘，只做一次）

### 1. 建立 repo 並上傳
```bash
cd project-sccd-plant              # 解壓縮後的資料夾
git init -b main
git add .
git commit -m "善意星系：初始框架"
gh repo create project-sccd-plant --public --source=. --push
```
> 用 GitHub Pages 免費方案需要 public repo。想要 private，需要 GitHub Pro／Team，或改用 Vercel 部署。

### 2. 修改主星設定
| 檔案 | 改什麼 |
|---|---|
| `src/site.config.ts` | `repoUrl` 改成你的 repo 網址；課程名稱、標題 |
| `.github/CODEOWNERS` | `@kaochieh224` 改成你的帳號（如不同） |
| `cities/demo-*` | 四個示範城市（一棟房子／村落／城鎮／大都市），**開課前刪除**（保留 `kaochieh224` 作為示範） |

### 3. 開啟 GitHub Pages
repo 的 **Settings → Pages → Build and deployment → Source** 選 **GitHub Actions**。
push 一次到 main，約 2 分鐘後網址會出現在 **Actions → 部署星系**。

### 4. 保護 main 分支
**Settings → Branches → Add branch ruleset**（或 Branch protection rule），對 `main` 開啟：
- ✅ Require a pull request before merging
- ✅ Require approvals：1
- ✅ Require review from Code Owners
- ✅ Require status checks to pass：選 `check`（城市檢查）
- ✅ Block force pushes

### 5. 建立標籤
```bash
gh label create core --color d4101a --description "老師核准的框架修改"
gh label create framework --color 171717 --description "框架提案"
```
> 學生設為 **Write** 權限，就能 push 分支、開 PR。Write 權限**也能加標籤**，所以 CI 會再確認 `core` 標籤是由 **maintain 或 admin** 權限的人加上，學生自己加的不算。
> 老師自己的帳號是 repo 擁有者（admin）；助教若要能核准框架提案，請設為 **Maintain**。

### 誰可以核准（擇一）
| 做法 | 設定 | 適合 |
|---|---|---|
| 老師審全部（預設） | `CODEOWNERS` 的 `*` 指向老師 | 人數少、想確保品質 |
| 老師＋助教 | `CODEOWNERS` 改成 `/cities/ @老師 @助教` | 30 人以上 |
| 同學互審城市 PR | 刪掉 CODEOWNERS 裡對 `/cities/` 的限制，保留 Require approvals 1 | 想練習 code review；框架提案仍由 CI 的 `core` 檢查把關 |

### 6. 邀請學生
```bash
gh api -X PUT repos/<你的帳號>/project-sccd-plant/collaborators/<學生帳號> -f permission=push
```
或到 **Settings → Collaborators → Add people**。人數多時，可以建 GitHub Organization 並用 Team 管理。

## 二、建議課程節奏（4 週）

| 週 | 主題 | 學生產出 | 協作概念 |
|---|---|---|---|
| 1 | 環境設定＋第一個 PR | `city.json` 填好，城市出現在星球上 | clone、branch、commit、PR、CI |
| 2 | 善意企劃＋蓋城市 | `proposal.json`＋`City.ts` | 公版與自由、CLAUDE.md、迭代 |
| 3 | 穿梭機路線＋子 UI | `scenes`＋`Page.tsx` | 小步 PR、review 回饋、修 CI |
| 4 | 框架提案週 | 分組提出並實作一個框架改進 | Issue 討論、相容性、code review |

**第 1 週的關鍵**：讓每個人在第一堂課結束前，看到自己的城市出現在線上的星球上。成就感決定了之後的投入程度。

## 三、Review 檢查表

### 城市 PR
- [ ] CI 三道檢查都通過
- [ ] 企劃內容是學生自己的想法（不是 AI 編的空話）
- [ ] 從主星降落、每一站穿梭機都飛得到、手機版不爆版
- [ ] 城市沒有把整顆星球拖慢（網格數量合理、沒有超大貼圖）
- [ ] 圖片有壓縮、有 alt

### 框架提案 PR（加 `core` 標籤前）
- [ ] 有對應的 Issue，且討論已有共識
- [ ] **沒有修改 `.github/workflows/`**，或修改內容你逐行看過（workflow 可以執行任意指令）
- [ ] 沒有新增來路不明的套件（看 `package.json` 與 `package-lock.json` 的變更）
- [ ] 本機 checkout 這個分支跑 `npm run build`，並抽看幾個城市
- [ ] 公版欄位改動向下相容

## 四、防護機制一覽

| 層 | 機制 | 擋什麼 | 可被繞過嗎 |
|---|---|---|---|
| Claude Code | `.claude/hooks/guard.mjs` | Claude 編輯城市以外的檔案 | 可以（`SOLAR_CORE=1`），這是教學用的提醒 |
| Claude Code | `CLAUDE.md` | 告訴 Claude 規則與流程 | 可以，屬於軟性約束 |
| CI | `check-scope.mjs` | 越界修改、一次改多個城市 | 不行，除非老師加 `core` 標籤 |
| CI | `build-registry.mjs` | 公版欄位錯誤、引用禁用套件、檔案過大 | 不行 |
| CI | `next build` | 任何會讓整站壞掉的錯誤 | 不行 |
| GitHub | Branch protection＋CODEOWNERS | 未經審核合併、直接 push main | 不行 |
| 執行時 | `Universe.tsx` 的 try/catch | 某人的 `City.ts` 出錯拖垮整顆星球 | — |

## 五、老師自己修改框架
```bash
SOLAR_CORE=1 claude                  # Mac
```
```powershell
$env:SOLAR_CORE="1"; claude          # Windows PowerShell
```
修改後照常開 PR、加上 `core` 標籤。建議老師也走 PR 流程，當作學生的示範。

## 六、常見狀況
| 狀況 | 處理 |
|---|---|
| 學生改錯別人的資料夾 | CI 會擋下；請學生用 Claude Code 還原：「把 cities/xxx 還原成 main 的版本」 |
| 兩個 PR 同時改 `package-lock.json` | 只會發生在框架提案；先合併一個，另一個請作者 `git pull origin main` 後重新 `npm install` |
| 某座城市讓網站變很慢 | 開 Issue 標記該同學；常見原因是 City.ts 網格太多（請改用 mergeGeometries 或 InstancedMesh）或圖片太大 |
| 城市位置變了 | 地塊依帳號雜湊分配，遇到衝突時順延；新同學加入偶爾會讓少數城市換位置（模擬：6 城加到 36 城，約 2 座換位）。scenes 是以城市為原點的座標，換位不受影響 |
| 學生沒有 Claude 付費方案 | Claude Code 需要 Pro 以上方案或 Console 帳號，開課前先確認 |
| Windows 上 hook 沒有作用 | hook 指令依賴 `$CLAUDE_PROJECT_DIR`；請在一台 Windows 電腦實測（未查證）：在學生的城市模式下請 Claude 改 `src/app/page.tsx`，應該會被擋下。沒被擋也不會出事，CI 仍會把關 |
| 學生的 Page.tsx 壞掉 | 只有那一塊會顯示錯誤訊息，星球與導覽照常運作；City.ts 壞掉則自動改用預設城市 |
