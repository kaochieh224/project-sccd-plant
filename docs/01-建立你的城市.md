# 01　建立你的地塊（作品入口）

> 檔名還叫「建立你的城市」，是舊名稱。資料夾 `cities/` 也一樣，意思是「地塊」：星圖上分給你的一塊地。

## 先理解這個網站是什麼

這個網站是探索者 studio 的**全班作品總站**。星圖上每個光點是一件作品，點進去可以看到作品介紹，並連到作品自己的展示頁與 GitHub repo。

**你的作品本體不在這裡。** 作品放在你自己的公開 repo 與展示頁（GitHub Pages 或 Vercel）。這個 repo 只放作品在總站上的入口：一句話描述、作品卡、穿梭機路線、一個小小的 3D 模型和降落頁。

計畫規定作品是非傳統類型，一般的網站和一般的遊戲都不做。所以不要在這裡做作品，這裡的網站只是全班作品的展示牆。計畫的完整規定（賽事、里程碑、評分）請看 Notion 的探索者計畫。

```
探索者計畫總站
├── 背景：3D 星圖、北極太空港、航線、雲        ← 全班共用，透過框架提案才能改
├── 母 UI：導覽列、穿梭機面板、作品導航         ← 全班共用，透過框架提案才能改
└── 你的地塊  cities/<你的帳號>/                ← 你是探索者
    ├── city.json      作品識別＋穿梭機站點   ← 公版欄位，內容自己填
    ├── work.json      作品卡                 ← 公版欄位，內容自己填
    ├── City.ts        3D 模型                ← 完全自由（選用）
    ├── Page.tsx       降落後的子 UI          ← 完全自由
    └── CLAUDE.md      設計意圖               ← 寫給 Claude Code 看
```

**受限的框架，自由的填充**：所有人用同一套欄位，主星才能把大家放上同一張星圖、讓穿梭機知道要停哪裡、彙整全班的作品卡；欄位以外的一切都由你決定。

> 你**不能**選地塊的位置。位置由你的 GitHub 帳號計算出來，就像你無法選擇自己出生在哪裡。偶爾有新同學加入時，少數地塊會搬到隔壁；你的模型與站點是以地塊中心為原點，搬家也不會壞。

每次打開 Claude Code，它都會列出你的任務進度並引導下一步。輸入 `/mission` 隨時查看。

## ① city.json：你的作品是什麼

| 欄位 | 說明 | 範例 |
|---|---|---|
| `name` | 作品名稱，16 字內 | `"燈塔港"` |
| `owner` | 探索者（你的名字） | `"高捷"` |
| `oneLiner` | **一句話作品描述**，40 字內，會顯示在星圖上。寫出觀眾在這件作品前會做什麼 | `"為第一次寫程式的人，點亮一座不會責備人的燈塔。"` |
| `color` | 作品主色，6 碼 hex | `"#4d96ff"` |
| `scale` | `"house"` 一棟房子、`"village"` 村落、`"town"` 城鎮、`"metropolis"` 大都市。只決定預設 3D 模型的大小 | `"village"` |
| `keywords` | 最多 3 個關鍵字，每個 10 字內 | `["引路", "示範"]` |
| `scenes` | 穿梭機站點，1–8 站（見 ③） | |

> 還沒寫 `City.ts` 之前，主星會依 `scale` 和 `color` 自動幫你長出一個預設模型，所以第一天就能出現在星圖上。

## ② work.json：你的作品卡

作品卡是全班同一套欄位，對應計畫的「非傳統三問」與四個階段。內容請從你自己的 `PLAN.md` 來。

| 欄位 | 問自己 | 字數 |
|---|---|---|
| `direction` | 作品方向：`"技術"`、`"議題"`、`"美學"` 三選一 | — |
| `audience` | 觀眾是誰？ | 40 |
| `competition` | 主攻賽事／類別 | 40 |
| `participation` | **第一問**：觀眾用什麼方式參與，和滑鼠、鍵盤、觸控螢幕有什麼不同？ | 120 |
| `architecture` | **第二問**：作品的架構和一般的網站或一般的遊戲差在哪裡？ | 120 |
| `essence` | **第三問**：拿掉哪一個部分，這件作品就變回傳統的東西？ | 120 |
| `stage` | 目前階段：`"前置期"`、`"做到可玩"`、`"做到展出"`、`"送出去"`、`"收成"` | — |
| `oneLinerEn` | 一句話作品描述的英文版（選填） | 120 字元 |
| `showcaseUrl` | 作品展示頁網址（選填，W4 起），要以 `https://` 開頭 | — |
| `repoUrl` | 作品的公開 GitHub repo 網址（選填），要以 `https://` 開頭 | — |

> 作品卡的內容請用你自己的話寫，三問尤其如此。Claude Code 可以幫你修句子，但不能幫你想作品，也不能替你回答這三問。

> 展示頁與 repo 的網址，等你的作品有了這兩個東西再填。展示頁是 W4 起要建的，建好後回來補上，任務進度的第 11 項就會完成。

## ③ 穿梭機站點 scenes：參觀者會看到什麼

降落你的地塊後，參觀者搭著穿梭機，一站一站地參觀。每一站就是一個**鏡頭位置**：

```json
{ "name": "燈塔下", "camera": [34, 9, 40], "target": [0, 70, 0], "note": "抬頭看，光一直都在。" }
```

| 欄位 | 意思 |
|---|---|
| `name` | 站名，12 字內 |
| `camera` | 鏡頭站在哪裡 `[x, 高度, z]`：x、z 在 ±250 內，高度 1–500 |
| `target` | 鏡頭看向哪裡：x、z 在 ±250 內，高度 -50–500，不能和 camera 同一點 |
| `note` | 到站時顯示的一句話（選填，60 字內） |

座標以地塊中心為原點，地面高度是 0。地塊半徑 120，建議蓋在高度 260 以內。最多 8 站。

**設計路線的訣竅**：像拍電影一樣想：先一個大全景（高、遠），再一步步靠近（低、近），最後停在你最想讓人看到的細節上。

```
請幫我設計 4 站的穿梭機路線：先從空中看整個模型，再降落到入口，
接著穿過兩根柱子之間，最後停在最亮的那一盞燈前。
```

## ④ City.ts：作品在星圖上的 3D 模型

把範本裡的 `City.example.ts` 改名為 `City.ts`，然後告訴 Claude Code 你想做什麼樣的模型。它是你作品在星圖上的樣子，不是作品本身：

```
我的作品是一排會躲人的燈，模型做成一排細細的光柱，有人靠近時會一根一根暗下去
```
```
做一座很高的霓虹塔：高架軌道繞著塔身，軌道上有光點在跑，
有人來參觀時，招牌會一個一個亮起來
```
```
我只想放一盞小小的檯燈在地上，但要很精緻：燈罩、燈座、一圈柔光
```

一棟房子到一整座都市都可以，尺度由你決定。還有三件事要知道：
- **會動**：`update(t, dt, info)` 每一格畫面都會執行，可以讓東西轉、飄、閃
- **會回應參觀者**：`info.visited` 是「有沒有人在參觀」，`info.scene` 是「停在第幾站」
- **壞了不會連累別人**：City.ts 出錯時，主星會自動改用預設模型

## ⑤ Page.tsx：降落後的子 UI

鏡頭飛進你的地塊後，畫面上疊著的就是你的 `Page.tsx`，整個頁面由你設計。這一頁適合放作品的簡介，並用連結帶觀眾去你的展示頁與 repo。

Page 會收到 `{ meta, work, plot }`：`meta` 是 city.json 的內容，`work` 是作品卡，`plot` 是地塊編號。

主星提供幾個零件（`@/kit`），可用可不用：

| 零件 | 作用 |
|---|---|
| `<Sky>` | 透明的天空窗，露出背後的 3D 模型；滑鼠可以穿透去拖曳環顧（要放在最外層） |
| `<Nameplate>` | 作品名牌 |
| `<SceneList>` | 穿梭機站點清單，點一下就飛過去 |
| `<WorkCard>` | 標準作品卡看板，吃 `work` 與 `meta` |
| `<Ground>` | 白色實心區塊 |
| `useShuttle()` | 知道參觀者停在第幾站、控制穿梭機（`go(i)`、`next()`、`prev()`） |

範本用了這些零件。老師的示範地塊 `cities/kaochieh224/`（燈塔港）則示範了：標題跟著站點改變、自己排作品卡、和主星完全不同的視覺風格。

### 和 Claude Code 對話的訣竅

| ✗ 太模糊 | ✓ 具體 |
|---|---|
| 「幫我做好看一點」 | 「作品卡區改成左右兩欄，左邊大標題，右邊用編號列出三問的答案」 |
| 「模型加點東西」 | 「在第 2 站的中間加一座噴水池，水會一直往上噴」 |
| 「改顏色」 | 「整個模型改成黃昏的感覺：橘色和紫色，每一扇窗都亮著暖黃色的燈」 |

更好的做法：
1. **先要方向**：「給我三種方向，用文字描述就好，先不要寫程式」
2. **一次只改一件事**：改完、看過、滿意了，再提下一個要求
3. **看不懂就問**：「你剛剛改了什麼？為什麼要加 'use client'？」
4. **出錯就貼**：把錯誤訊息整段貼給 Claude Code
5. **養成習慣**：每次下課前請 Claude Code 更新你的 `CLAUDE.md`

## 規則（違反時，CI 會擋下你的 PR）
- 只能修改自己的資料夾 `cities/<帳號>/`
- 只能引用：自己資料夾內的檔案、`react`、`next/link`、`three`、`three/addons/…`、`@/kit`
- 樣式要寫在 `*.module.css`，不能用 `:global`
- 單一檔案 ≤ 2 MB，整個地塊資料夾 ≤ 8 MB（圖片請先轉成 `.webp`）

隨時可以輸入 `/check` 自我檢查。做好了就看 [02 送出 PR](./02-送出PR.md)。
