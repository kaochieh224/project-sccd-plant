# 03　框架提案：讓整張星圖變得更好

背景（3D 宇宙、主星）和母 UI 屬於全班。任何人都可以提案修改，但因為會影響每一個人，所以要經過討論與審核。這正是真實團隊協作的方式。

## 可以提案什麼？
- 主星：例如顯示全班作品所在階段的統計、依關鍵字串連相關作品
- 3D 星球：例如加入日夜循環、季節，或讓有共同關鍵字的作品之間出現航線
- 母 UI：例如穿梭機面板加上自動導覽、作品搜尋
- 公版欄位：例如 `work.json` 多一個「合作夥伴」欄位
- 主星零件：例如 `@/kit` 新增一個圖片輪播元件
- 新套件：例如希望能用 `gsap` 做動畫

## 流程

```
① 開 Issue ──▶ ② 討論、取得同意 ──▶ ③ core/ 分支實作 ──▶ ④ 開 PR ──▶ ⑤ 老師加 core 標籤＋review ──▶ ⑥ 合併
```

在 Claude Code 輸入 `/propose`，它會帶你完成全部流程。

### ① 開 Issue
到 GitHub repo 的 **Issues → New issue → 🛰 框架提案**，或請 Claude Code 幫你開。寫清楚三件事：想改什麼、為什麼、會影響誰。

### ② 討論
其他同學可以留言支持、提出疑慮或一起加入。老師同意後，Issue 會被指派給你。

### ③ 實作：切換到「框架提案模式」
平常 Claude Code 只能修改你的地塊（hook 會擋下其他檔案）。框架提案時，要用這個方式啟動：

**Mac**
```bash
git switch main && git pull
git switch -c core/<簡短描述>
SOLAR_CORE=1 claude
```
**Windows（PowerShell）**
```powershell
git switch main; git pull
git switch -c core/<簡短描述>
$env:SOLAR_CORE="1"; claude
```
> 這個設定在同一個 PowerShell 視窗裡會一直有效。提案做完、要回去做自己的作品入口時，先執行 `Remove-Item Env:SOLAR_CORE`，或直接開一個新視窗。

### ④ 開 PR
PR 內容寫上 `Closes #<Issue編號>`，合併時 Issue 會自動關閉。

### ⑤ 等待審核
CI 的「越界檢查」會先顯示 ✗，這是**正常的**。老師 review 後會加上 `core` 標籤，檢查就會重跑並通過。

## 黃金規則
1. **不能讓任何人的作品入口壞掉。** 改完一定要 `npm run build`，並實際打開至少三位別人的地塊確認。
2. **公版欄位要向下相容。** 新增欄位設為選填；如果一定要必填，要一併幫所有現有地塊補上（這需要老師協助）。
3. **一次只提一件事。** 小提案容易討論、容易審核。
4. **框架提案和自己的地塊分開送 PR。**
