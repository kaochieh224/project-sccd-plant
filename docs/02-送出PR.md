# 02　送出 Pull Request

在 Claude Code 裡輸入 `/submit`，它會帶你一步一步完成，並解釋每一步在做什麼。這份文件讓你知道背後發生了什麼。

## 五個名詞

| 名詞 | 意思 | 比喻 |
|---|---|---|
| **main** | 正式版，線上網站就是它 | 已經出版的書 |
| **branch（分支）** | 從 main 複製出來的工作版本 | 你的草稿本 |
| **commit** | 一次存檔，附上說明 | 草稿本上標記「這頁改了什麼」 |
| **push** | 把存檔上傳到 GitHub | 把草稿本交到老師桌上 |
| **Pull Request（PR）** | 請求把你的草稿合併進正式版 | 「老師，可以把我這頁收進書裡嗎？」 |

## 流程

```
main ──────────────────────────●──────────▶  合併後自動上線
       \                      ↑
        city/你-描述 ─●─●─●─┘
                      commit  ↑
                         PR ＋ 自動檢查 ＋ 老師 review
```

1. **開分支**：`git switch -c city/<帳號>-<描述>`
2. **存檔**：`git add cities/<帳號>/`，然後 `git commit -m "潮間帶小鎮：完成企劃版面"`
3. **上傳**：`git push -u origin <分支名稱>`
4. **開 PR**：`gh pr create`，依範本填寫
5. **自動檢查**（約 2 分鐘），PR 頁面會出現三道檢查：
   - ① 越界檢查：只改了自己的城市嗎？
   - ② 公版規格檢查：city.json、proposal.json 格式對嗎？
   - ③ 建置：整顆星球還能正常建出來嗎？
6. **老師 review**：可能會留言請你修改。修改後再 commit、push，PR 會自動更新。
7. **合併**：老師按下 Merge，約 2 分鐘後，你的城市就會出現在線上的星球上。

## 檢查沒過怎麼辦？
1. 在 PR 頁面點開紅色 ✗ 的檢查，找到中文錯誤訊息
2. 整段複製，貼給 Claude Code：「CI 出現這個錯誤，幫我修」
3. 修好後 commit、push，檢查會自動重跑

## 下一次上課，怎麼繼續？
```bash
cd ~/<repo 名稱>
git switch main
git pull          # 下載別人新加入的城市
claude
```
然後告訴 Claude Code：「我要繼續做我的城市，幫我開一個新分支」。

> 每完成一個段落就送一次 PR，不要累積一大包。小步快跑，衝突最少。
